### 2026-09-21 기준선에서 틀린 것

범용으로 전환했지만 모델은 아직 옛 도메인 데이터로 학습된 상태다. 그래서 틀리는 자리가 한쪽으로 쏠린다.

| # | 문항 | 기대 | 실제 | 원인 |
|---|---|---|---|---|
| 1 | 일반 약속 | done, meeting | need_info | 절차가 있다고 보고 되물었다 |
| 3 | 절차 단서 없음 | access 를 비움 | required=true | 장소 이름만 보고 절차가 있다고 단정 |
| 5 | 픽업 | meeting | visit | 같은 원인 |
| 9 | 짧은 반말 | meeting | visit | 같은 원인 |
| 6 | 시각 없음 | need_info | failed | 범위 밖 표시와 참석자가 같이 나와 스키마가 막았다 (코드에서 정리) |
| 10 | 범위 밖 | out_of_scope | failed | 같은 원인 |

6·10 은 코드에서 고쳤다 (`llm._parse` 가 모순을 정리한다). 고친 뒤 다시 재니 단계 정확도가
0.60 에서 0.80 으로 올랐다. 모델은 그대로다.

1·3·5·9 는 재학습 대상이다. 넷 다 원인이 같다. 학습 데이터가 전부 기지·사무실 방문이라
"어디서 만난다"를 보면 절차가 있다고 본다. 학습 데이터 939건을 범용 문장으로 새로 만들어
두었고(meeting 462·visit 422·범위 밖 55), 재학습 뒤 같은 셋으로 다시 잰다.

재학습으로 이 넷이 풀리면 단계 정확도는 1.0, 슬롯 정확도는 1.0 이 되어야 한다.
안 되면 데이터가 부족한 것이고, 그때는 어느 갈래가 모자란지 이 표를 보고 정한다.

`gemini-3.5-flash-lite` 로 간다. 한 단계 위 모델(`gemini-3.5-flash`)은 더 느린데 정확도는 오히려 낮았다.
값이 비싼 모델이 늘 나은 것은 아니다.

처음 붙였을 때 0.70/0.778 이던 것을 1.00/1.00 까지 올린 것은 프롬프트 두 판과 코드 두 군데다.

프롬프트 (Langfuse converge/slot-extract v3, v4)
- preset 규칙을 meeting/visit 으로 바꿨다. v2 는 아직 옛 도메인을 가르치고 있었다
- access 를 세 갈래로 나눠 적었다. 아무나 들어가는 자리면 false, 절차가 나오면 true,
  사무실인데 절차 이야기가 없으면 비우고 되묻기
- "등록을 해야 한다" 는 절차가 있다는 말이지 했다는 말이 아니다. applied 를 단정하지 않는다

코드
- pipeline._drop_needless: 남의 차를 얻어 타는 사람의 출발지는 묻지 않는다.
  소요시간을 탑승 지점부터 재므로 없어도 계산된다
- llm.fill_pickup_transport: 얻어 타는 사람의 이동수단을 운전자 것으로 채운다.
  "차로 오시나요" 는 물을 필요가 없는 질문이었다

### 파인튜닝은 후보로 남긴다

버리지 않는다. 다만 지금 쓰지 않는다.

- 왜 안 쓰나: CPU 로는 요청당 16~20초라 쓸 수 없고, 제대로 쓰려면 GPU 서버를 띄워야 한다.
  사이드 프로젝트에 그 고정비를 들일 이유가 없다
- 언제 다시 보나: 호출량이 무료 할당을 넘거나, 외부 API 없이 돌려야 할 일이 생기면
- 남겨 둔 것: `backend/app/services/slot_model.py`(GGUF 서빙), `backend/app/models/`(문법·프롬프트 설정),
  `finetune/`(학습 파이프라인), 학습 데이터 939건(범용 문장으로 새로 만든 것, 저장소 밖 LLM FT 폴더)
- 되돌리는 법: `.env` 의 `MODEL_SMALL` 을 주석 처리하면 로컬 GGUF 로 돌아간다
